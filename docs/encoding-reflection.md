# The encoding-reflection class

This page states what the `encoding-reflection` exemption class of deadset-go retains, for a maintainer reading why an encoded or reflected type kept a member. A type whose values reach a consumer that names members by string at run time keeps the members that consumer reads. Those are the exported fields, every field carrying a struct tag, and the methods the consumer resolves by name.

The destinations, and what each retains:

- Fields and the methods it resolves by name for an argument of a function or method of `encoding/json`, `encoding/json/v2`, `encoding/xml` or `encoding/gob`. A decoding entry point fills fields through reflection, which reads none, so it retains its methods alone. An encoder skips a field whose tag for that encoder is exactly `-`, and an XML decoding entry point reads the `XMLName` field. A JSON decoding entry point retains fields as well in a program that calls `(*json.Decoder).DisallowUnknownFields` or names `json.RejectUnknownMembers`.
- Fields alone for a `database/sql` scan target and an argument of `reflect.DeepEqual`. Fields alone also for an argument of any other `reflect` function in a program that calls none of the method finders `Method`, `MethodByName` and `NumMethod`.
- Fields and the `LogValue` method for a `log/slog` logging call or attribute constructor. An argument for a `context.Context` parameter, of any destination, reaches none, because a handler reads a context by key.
- Fields and the exported methods for a template engine. The same holds for an argument of any other function of `reflect` in a program that calls one of those method finders, except a call whose result heads a chain of `reflect.Value` or `reflect.Type` methods, none a method finder, that ends in neither type, directly or through a local variable whose every use heads such a chain, which retains fields alone. A conversion to `sort.Interface` is no destination here: interface satisfaction retains the three methods it requires. A template set the program executes straight from a variable, written once from constant text, constant file names or patterns, or an embedded file system's constant patterns, and only executed, looked up or named, reads only the fields and the methods its templates name, embedded fields, and `String`, `Error` and `Format`, which the engine prints a value through, and the same of each type a method it calls returns. That holds outside a library, and where no `html/template` file of the set holds a `<script>` element or an event-handler attribute, whose engine encodes a value there whole.
- For a destination outside the analyzed program, the members [a value that leaves the analysis](exemptions.md#what-leaves-the-analysis-is-fully-reachable) keeps.
- No field for a function or method outside the analyzed program whose name begins `Unmarshal`, `Decode`, `Bind`, `ShouldBind` or `MustBind`, unless its own body hands the value to an encoder, a template engine, reflection or a formatting function. Such a callee fills the fields and may read them, as a validating binder does, so a field only it fills is reported at the confidence `possible` rather than held live.

An encoder resolves a method by name in the direction its entry point works in. An entry point whose name begins `Encode` or `Marshal` retains the encoding methods. One whose name begins `Decode` or `Unmarshal` retains the decoding methods. One whose name begins with neither retains both, because it takes a value for either direction.

| Package | Encoding | Decoding |
| --- | --- | --- |
| `encoding/json`, `encoding/json/v2` | `AppendText`, `MarshalJSON`, `MarshalJSONTo`, `MarshalText` | `UnmarshalJSON`, `UnmarshalJSONFrom`, `UnmarshalText` |
| `encoding/xml` | `MarshalText`, `MarshalXML`, `MarshalXMLAttr` | `UnmarshalText`, `UnmarshalXML`, `UnmarshalXMLAttr` |
| `encoding/gob` | `GobEncode`, `MarshalBinary` | `GobDecode`, `UnmarshalBinary` |

An encoder calls the encoding method of a type that has one instead of walking its fields: `MarshalJSON`, `MarshalJSONTo` or `MarshalText` for JSON, `MarshalXML` or `MarshalText` for XML, `GobEncode` or `MarshalBinary` for gob. So it reads none of that type's fields and walks no further through them. A method promoted from an embedded type counts. A method with a pointer receiver counts only where every value of the type the walk meets is addressable: met through a pointer or as a slice element, and not as the value handed to the encoder, a map key or value, or a value an interface holds.

A value reaches through a pointer, a slice, an array, a map key or value and an embedded field. It also reaches through the fields of a struct type with no name. From every type so reached, it reaches through that type's fields again until no further type joins, because an encoder walks the whole value rather than its outermost type.

A field that is an interface, or holds interface elements or map values, reaches the types the program stores in it. A store is a composite literal, an assignment, an `append` or an index assignment. A stored parameter stands for every argument the program's calls pass for it. An argument holding interface elements or map values reaches the stored types the same way. It may be a literal, a variable, a parameter or a field selector. An interface-typed field read back, `h.value` handed to an encoder, reaches what the program stores in that field.

A value stored there that is itself a composite literal, a field or a variable holding interface elements or map values carries what that container holds, so a map literal assigned to an `any` field, or returned as `any`, reaches the types of the values it holds. A call through a method of an interface holds what each method of the program's defined types implementing it returns. An argument of a function outside the analyzed program that names such a container reaches what it holds too.

A composite literal argument reaches the type of each value it writes into an interface-typed position, and so does each literal it nests. An argument of a defined interface type reaches every type the program converts to that interface. A conversion to `any` reaches nothing by itself. Both hold for an argument a function of the program forwards to a destination.

A decoding entry point also reads each pointer, interface or map field the program writes. It decodes into the value that field holds.

A destination that reads fields keeps only a field the program writes, by a composite literal, an assignment, an increment or a decrement, or a conversion that produces the field's struct type. A write in a test file counts only in a run that counts test references. A field a decoder of production code fills counts as written, so a value the program decodes and encodes again keeps the fields it relays. So does a field an outside callee may fill: one handed a pointer to the value, whatever its name, or a generic function that makes the value from none of its arguments. A field nothing writes that only such a callee fills is reported at the confidence `possible`. A field nothing writes or decodes is reported, because the receiver reads a value the program never gave it.

An assertion to an interface of what `Interface` returns for a `reflect.Value` holding a struct field, read by `Field`, `FieldByIndex`, `FieldByName` or `FieldByNameFunc` from a value `reflect.ValueOf` gives, through `Elem` and `reflect.Indirect`, converts each exported field of that struct. It retains the methods by which each exported field type implements that interface.

A method is retained where the defined type declares it, so a method promoted from an embedded type is retained where the embedded type is reached.
